# ADR-0009: Автодеплой Docker-образа на сервер Timeweb Cloud

- **Статус:** Предложено
- **Дата:** 2026-11-14
- **Связанные ADR:** [ADR-0006](0006-hosting-github-pages.md), [ADR-0007](0007-docker-image.md)

## Контекст

Нужна автоматическая сборка и публикация сайта на собственный сервер: каждый push в `main`
должен без ручных действий оказаться на сервере. У владельца есть аккаунт Timeweb Cloud
и CLI `twc`. Docker-образ сайта уже есть (ADR-0007). Домен silart.com пока не подключаем —
сайт открывается по IP-адресу сервера по HTTP.

## Рассмотренные варианты

1. **VPS в Timeweb Cloud + GitHub Actions пушит образ в ghcr.io и деплоит по SSH.**
2. **Сервер сам опрашивает реестр (Watchtower)** — не нужен SSH-доступ из CI, но не видно,
   прошёл ли деплой, нет проверки и отката, ошибка обнаруживается не сразу.
3. **Timeweb Cloud Apps (PaaS)** — меньше администрирования, но меньше контроля над
   контейнером и его настройками безопасности, привязка к платформе.

## Решение

Вариант 1:

- Сервер: Ubuntu 24.04, минимальный тариф, регион ru-1, создаётся через `twc server create`
  с `deploy/cloud-init.yaml` (ставит Docker, создаёт пользователя `deploy`), вход по паролю
  отключён. Firewall Timeweb пропускает только 22/tcp и 80/tcp.
- Реестр: GitHub Container Registry, образ `ghcr.io/siprofy/silart-landing:<sha коммита>`.
- Workflow `.github/workflows/deploy-server.yml`: сборка и публикация образа → деплой.
  Действия закреплены по SHA, права `GITHUB_TOKEN` минимальные для каждой задачи.
- SSH-ключ CI ограничен на сервере (`restrict,command=...` в `authorized_keys`): с ним можно
  только запустить `/usr/local/bin/silart-deploy <sha>`, ни shell, ни проброса портов.
- `silart-deploy` скачивает образ (токен ghcr живёт только во время задачи), запускает
  `docker compose up --wait`, проверяет `/healthz` и при ошибке возвращает прошлую версию.
- Адрес сайта для сборки — переменная репозитория `SITE_URL` (сейчас `http://<IP>`).
- Отдельный админский SSH-ключ (root) — для первичной настройки и обслуживания.

## Обоснование

- Деплой виден в GitHub: зелёная или красная галочка у коммита, ссылка на сайт в environment.
- Тег = хеш коммита: всегда понятно, что запущено, откат — запуск прошлого тега.
- Компрометация ключа CI не даёт shell на сервере — только повторный деплой образа из ghcr.
- Без сторонних SSH-actions: обычные `ssh`, меньше зависимостей в цепочке поставки.

## Последствия

- Сервер платный (посуточное списание в Timeweb), обновления ОС ставятся автоматически
  (`unattended-upgrades`), но сервер нужно иногда проверять.
- Пользователь `deploy` в группе `docker` — фактически root-доступ, поэтому ключ ограничен
  forced command; менять файлы сервера (`deploy/*`) может только админ.
- Без домена нет HTTPS. При подключении silart.com: A-запись на IP, открыть 443/tcp,
  добавить Caddy перед контейнером (отдельный ADR или дополнение к этому),
  `SITE_URL=https://silart.com`.
- GitHub Pages (ADR-0006) пока продолжает работать параллельно; отключить, когда сервер
  проработает стабильно.
