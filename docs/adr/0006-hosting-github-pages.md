# ADR-0006: Хостинг — GitHub Pages

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Связанные ADR:** заменяет [ADR-0005](0005-hosting-render.md)

## Контекст

По [ADR-0005](0005-hosting-render.md) сайт планировалось разместить на Render. При создании сервиса
Render потребовал привязать банковскую карту (проверка аккаунта), хотя Static Site бесплатен.
Владелец проекта не хочет привязывать карту.

Требования к хостингу прежние: статический сайт, HTTPS, CDN, автодеплой из GitHub, возможность
подключить домен silart.com. Дополнительно — без новых аккаунтов и платёжных данных.

## Рассмотренные варианты

1. **GitHub Pages** — репозиторий уже на GitHub, отдельный аккаунт не нужен. Бесплатно для
   публичных репозиториев. Сборка и деплой через GitHub Actions.
2. **Cloudflare Pages** — бесплатно, быстрый CDN, но нужен отдельный аккаунт Cloudflare.
3. **Netlify** — бесплатно, удобные формы, но нужен отдельный аккаунт.
4. **Render с картой** — отклонено владельцем.

## Решение

**GitHub Pages**, деплой через GitHub Actions (`.github/workflows/deploy.yml`) при каждом push
в `main`. Адрес до подключения домена: https://siprofy.github.io/silart-landing/.

Сайт живёт в подпапке `/silart-landing/`, поэтому:

- `base` и `site` в `astro.config.mjs` задаются переменными `BASE_PATH` и `SITE_URL` при сборке;
- все внутренние ссылки строятся через `url()` из `src/lib/url.ts`.

Без переменных сайт собирается под корень `https://silart.com` — так будет после подключения домена.

## Последствия

- Репозиторий должен оставаться публичным (Pages для приватных репозиториев — платный тариф GitHub).
- Нельзя писать внутренние ссылки строкой `href="/..."` — только через `url()`, иначе они сломаются
  в подпапке.
- Нет серверных функций и обработки форм — для формы заявки понадобится внешний сервис
  (отдельный ADR). Netlify/Cloudflare остаются запасным вариантом, если это станет критично.
- При подключении silart.com: добавить домен в настройках Pages и DNS, убрать `BASE_PATH`
  и поменять `SITE_URL` в workflow.
