# ADR-0008: PDF-каталог в репозитории, поиск и подбор на стороне браузера

- **Статус:** Предложено
- **Дата:** 2026-11-12
- **Связанные ADR:** [ADR-0002](0002-site-architecture-approach.md), [ADR-0006](0006-hosting-github-pages.md)

## Контекст

Нужно: дать скачать «Каталог продукции 2026» (PDF, 100 страниц), сделать поиск по сайту и
виджет подбора оборудования на главной. Сайт статический (ADR-0002), хостинг — GitHub Pages
(ADR-0006): серверного кода нет. Исходный PDF из InDesign весит 31,7 МБ.

## Рассмотренные варианты

1. PDF в `public/`, данные серий — в TypeScript, поиск и подбор — скрипт в браузере.
2. PDF во внешнем хранилище (S3, Яндекс Диск), поиск через внешний сервис (Algolia, Pagefind).
3. Серверный поиск и расчёт (API) — требует отказаться от статического хостинга.

## Решение

Вариант 1.

- PDF пережат (изображения до 150 dpi, подмножества шрифтов) до ~26 МБ и лежит в
  `public/catalog/silart-catalog-2026.pdf`, обложка — `silart-catalog-2026-cover.jpg`.
- Серии, модели и номера страниц PDF — в `src/data/products.ts`. Это единый источник для
  поиска (`/search/`) и подбора (`#selector` на главной). Ссылки «Стр. N» ведут на
  `…pdf#page=N`, пока нет карточек товаров.
- Поисковый индекс собирается при сборке и встраивается в страницу как JSON; поиск —
  в браузере, с поддержкой артикулов без дефисов, неправильной раскладки и похожей кириллицы.
- Подбор — оценочный расчёт по площади стенок шкафа (IEC/TR 60890, k = 5,5 Вт/м²·К) и
  выбор моделей из того же набора данных.

## Обоснование

Без внешних сервисов, ключей и затрат; работает на любом статическом хостинге и в Docker-образе
(ADR-0007). Данных немного (~30 серий с основными моделями) — индекс весит единицы килобайт.
Внешнее хранилище для одного файла избыточно, а лимиты GitHub (100 МБ на файл) соблюдены.

## Последствия

- Каждая новая версия каталога добавляет ~26 МБ в историю git. Если каталог будет обновляться
  чаще пары раз в год — перенести PDF в Git LFS или внешнее хранилище.
- При выходе нового каталога нужно обновить `src/data/products.ts` (модели и номера страниц).
- Когда появятся страницы товаров, ссылки поиска и подбора переводятся с PDF на них, а
  `products.ts` объединяется с `catalog.ts`.
- Расчёт в виджете оценочный; на это прямо указано в интерфейсе со ссылкой на заявку.
