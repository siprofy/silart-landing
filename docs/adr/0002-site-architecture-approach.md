# ADR-0002: Архитектурный подход к сайту — генератор статических сайтов

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Связанные ADR:** [ADR-0001](0001-record-architecture-decisions.md)

## Контекст

silart.com — сайт производителя оборудования для климат-контроля шкафов и стоек
(кондиционеры, вентиляторы, нагреватели, аксессуары). Структура — в [site-structure.md](../site-structure.md).

Ключевые требования:

- **Каталог продукции:** 4 категории → 12 групп → 45 серий/типов изделий. У каждой серии —
  описание, технические характеристики, модели, PDF-документация, изображения.
  Онлайн-продаж (корзины, оплаты) нет — есть раздел «Где купить».
- **SEO и скорость** — основной канал привлечения B2B-клиентов; страницы должны быть
  быстро индексируемыми и с чистыми URL.
- **Регулярно пополняемый контент:** новости, статьи и обзоры.
- **Немного интерактива:** формы обратной связи/запроса, поиск по каталогу,
  возможно — фильтр по характеристикам и калькуляторы «Подбора и расчётов».
- **Небольшая команда**, минимум сопровождения и затрат на инфраструктуру.
- Каталог должен расти без переделки архитектуры.

## Рассмотренные варианты

1. **Статические страницы вручную** (HTML/CSS без сборки).
2. **Генератор статических сайтов (SSG)** — страницы собираются при деплое из шаблонов
   и контента (Markdown/JSON/YAML) в репозитории. Примеры: Astro, Hugo, Eleventy.
3. **Классическая CMS** (WordPress, 1С-Битрикс и т.п.) — серверный рендеринг с базой данных
   и админкой.
4. **SSR/гибридный фреймворк** (Next.js, Nuxt) с собственным сервером.
5. **SaaS-конструктор** (Tilda, Webflow).

## Сравнение

| Критерий                      | 1. Вручную | 2. SSG | 3. CMS | 4. SSR | 5. Конструктор |
|-------------------------------|:----------:|:------:|:------:|:------:|:--------------:|
| Масштабирование каталога      | ✗ | ✓ | ✓ | ✓ | ~ |
| SEO и скорость                | ✓ | ✓ | ~ | ✓ | ~ |
| Стоимость и простота хостинга | ✓ | ✓ | ✗ | ~ | ~ (подписка) |
| Безопасность (поверхность атак)| ✓ | ✓ | ✗ | ~ | ✓ |
| Редактирование без разработчика| ✗ | ~ | ✓ | ~ | ✓ |
| Контроль и версионирование (git)| ✓ | ✓ | ✗ | ✓ | ✗ |
| Динамика (формы, поиск, фильтр)| ✗ | ~ | ✓ | ✓ | ~ |
| Независимость от вендора      | ✓ | ✓ | ~ | ✓ | ✗ |

✓ — хорошо, ~ — с оговорками, ✗ — плохо.

Коротко по вариантам:

1. **Вручную** — подходит только для одностраничника. На 45+ страницах серий шапка, меню
   и разметка дублируются, любое изменение превращается в правку десятков файлов.
2. **SSG** — шаблоны (страница серии, страница группы) + данные о продуктах. Добавить серию —
   добавить файл с данными. На выходе обычные HTML-файлы: максимальная скорость,
   бесплатный или дешёвый хостинг на CDN, нечего взламывать. Формы и поиск решаются
   внешним сервисом / serverless-функцией и клиентским поиском по заранее собранному индексу.
3. **CMS** — удобная админка, но нужен сервер, БД, обновления и защита; медленнее без
   кэширования; изменения не проходят через git и ADR. Избыточно для каталога без продаж.
4. **SSR** — даёт динамику на каждый запрос, которая нам не нужна: каталог меняется редко.
   Платим сервером и сложностью без выгоды. Многие SSR-фреймворки умеют статический
   экспорт — то есть по сути сводятся к варианту 2.
5. **Конструктор** — быстрый старт, но слабый контроль над структурой каталога и SEO,
   привязка к платформе, нет версионирования, ежемесячная подписка.

## Решение

Использовать **генератор статических сайтов**. Контент (продукция, статьи, новости,
служебные страницы) хранится в репозитории в виде Markdown и структурированных данных
(content-as-code), сайт собирается в статический HTML и публикуется на CDN.

Динамические функции добавляются точечно, не меняя подхода:

- формы — через form-сервис или serverless-функцию хостинга;
- поиск — клиентский, по индексу, собираемому при сборке;
- калькуляторы подбора — клиентский JavaScript на отдельных страницах.

## Последствия

**Плюсы**

- Каталог масштабируется добавлением файлов с данными, без новых шаблонов.
- Высокая скорость загрузки и хорошая индексация.
- Минимальная стоимость хостинга, почти нулевое сопровождение сервера.
- Весь контент и его история — в git.

**Минусы и риски**

- Редактировать контент без навыков работы с git/Markdown неудобно.
  Если понадобится — подключить git-based или headless CMS поверх SSG
  (отдельный ADR), архитектура это допускает.
- Любое изменение контента требует пересборки (секунды–минуты, автоматически в CI).
- Если в будущем появятся личный кабинет, цены по клиентам или онлайн-заказы —
  подход придётся пересмотреть.

**Следующие решения (отдельные ADR)**

- Выбор конкретного генератора (кандидаты: Astro, Hugo, Eleventy).
- Модель данных каталога и схема URL.
- Хостинг и CI/CD.
- Языковые версии (нужна ли английская версия для silart.com).
- Сервис обработки форм.
