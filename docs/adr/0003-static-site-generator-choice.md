# ADR-0003: Генератор статических сайтов — Astro

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Связанные ADR:** [ADR-0002](0002-site-architecture-approach.md)

## Контекст

По [ADR-0002](0002-site-architecture-approach.md) сайт собирается генератором статических сайтов.
Нужно выбрать конкретный инструмент. Требования к нему:

- шаблоны для типовых страниц каталога (категория → группа → серия) из структурированных данных;
- типизированный контент (характеристики, модели, документы), чтобы ошибки в данных
  ловились при сборке, а не на проде;
- компонентный подход к вёрстке — блоки переиспользуются между страницами;
- возможность точечно добавить интерактив (поиск, фильтры, калькуляторы подбора),
  не превращая сайт в SPA;
- по умолчанию ноль JavaScript на клиенте, хорошие показатели скорости;
- распространённый стек, документация, лёгкий найм.

## Рассмотренные варианты

1. **Astro** — JS/TypeScript, компоненты `.astro`, Content Collections со схемами.
2. **Hugo** — Go, очень быстрая сборка, шаблоны Go templates.
3. **Eleventy (11ty)** — JS, минималистичный, несколько шаблонизаторов на выбор.

## Сравнение

| Критерий                              | Astro | Hugo | Eleventy |
|---------------------------------------|:-----:|:----:|:--------:|
| Типизированный контент (схемы)        | ✓ (Content Collections + Zod) | ~ | ✗ (вручную) |
| Компонентная вёрстка                  | ✓ | ~ (partials) | ~ |
| Точечный интерактив («острова»)       | ✓ | ✗ | ~ |
| JS на клиенте по умолчанию            | 0 | 0 | 0 |
| Скорость сборки                       | ~ | ✓ | ✓ |
| Порог входа для фронтенд-разработчика | ✓ | ~ (Go templates) | ✓ |
| Экосистема (sitemap, изображения, i18n)| ✓ | ✓ | ~ |

## Решение

Использовать **Astro** с TypeScript.

## Обоснование

- Content Collections со схемами дают проверяемую модель данных каталога — главное для сайта
  с десятками однотипных страниц серий.
- Компоненты и «острова» позволяют держать сайт статическим и добавлять интерактив только там,
  где он нужен (подбор, поиск).
- Встроенные оптимизация изображений, i18n-роутинг и интеграции (sitemap) закрывают
  ближайшие задачи без своих велосипедов.
- Hugo быстрее собирает, но при сотне страниц разница несущественна, а Go templates
  неудобны для компонентной вёрстки и интерактива.
- Eleventy гибок, но схемы данных и интерактив пришлось бы собирать самим.

## Последствия

- Нужен Node.js для разработки и сборки; зависимости — через npm.
- Стили — обычный CSS с CSS-переменными (дизайн-токены), без CSS-фреймворка на старте;
  при необходимости — отдельный ADR.
- Следующие ADR: модель данных каталога и схема URL, хостинг и CI/CD.
