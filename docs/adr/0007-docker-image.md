# ADR-0007: Docker-образ сайта (nginx + статика)

- **Статус:** Предложено
- **Дата:** 2026-11-12
- **Связанные ADR:** [ADR-0002](0002-site-architecture-approach.md), [ADR-0006](0006-hosting-github-pages.md)

## Контекст

Нужна возможность опубликовать сайт не только на GitHub Pages, но и на любом сервере или
платформе, которая запускает контейнеры. Сайт статический (ADR-0002): после `astro build`
остаётся папка `dist/`, серверный код не нужен.

## Рассмотренные варианты

1. **Многостадийный образ: Node собирает, nginx раздаёт** — в итоговом образе нет Node.js
   и `node_modules`, только статика и веб-сервер; образ маленький (~90 МБ), меньше поверхность атаки.
2. **Образ на Node с `astro preview`** — проще, но `preview` не предназначен для продакшена,
   образ тяжелее и тащит все зависимости.
3. **Собирать `dist/` на хосте и копировать в nginx** — сборка зависит от окружения разработчика,
   результат невоспроизводим.

## Решение

Вариант 1:

- `Dockerfile`: стадия `build` на `node:24.x-alpine` (как `.node-version`), стадия `runtime` на
  `nginxinc/nginx-unprivileged` — nginx работает не от root, на порту 8080.
- Версии базовых образов закреплены точно, без `:latest`.
- `SITE_URL` и `BASE_PATH` передаются как build args — те же переменные, что в GitHub Actions.
- `docker/nginx.conf`: долгий кеш для `/_astro/`, gzip, заголовки безопасности, `/healthz`
  для HEALTHCHECK.
- `compose.yaml` для локального запуска: файловая система только для чтения, `cap_drop: ALL`,
  `no-new-privileges`, порт открыт только на `127.0.0.1`.

Инструкция — [docs/docker.md](../docker.md).

## Последствия

- GitHub Pages (ADR-0006) остаётся основным хостингом; Docker — дополнительный способ публикации.
- Базовые образы нужно периодически обновлять (новые теги в `Dockerfile`) ради исправлений безопасности.
- HTTPS в образ не входит — его обеспечивает прокси или платформа перед контейнером.
- Если появится серверная логика (формы и т. п.), образ придётся пересмотреть отдельным ADR.
