Правила для работы с этим репозиторием (для Claude и людей).

## Проект

Сайт silart.com на Astro, статический (ADR-0002, ADR-0003). Решения фиксируются в
[docs/adr/](docs/adr/README.md): значимое изменение — новый ADR со статусом «Предложено».
Хостинг — GitHub Pages ([ADR-0006](docs/adr/0006-hosting-github-pages.md)); Docker-образ —

Внутренние ссылки — только через `url()` из `src/lib/url.ts` (сайт может жить в подпапке).

## Окружение: ничего не ставить «куда попало»

Компьютер — Windows с scoop, uv, WSL2 (Ubuntu) и Docker Desktop. Инструменты изолируются:

| Что | Как | Нельзя |
|-----|-----|--------|
| CLI на Python | `uvx <пакет>` (разово) или `uv tool install <пакет>` | `pip install --user`, `pip install` в системный Python |
| Нативные CLI для Windows | `scoop install <пакет>` | скачанные вручную `.exe` в произвольных папках |
| Работа с серверами, SSH, bash, OpenTofu | внутри WSL Ubuntu или контейнера | ключи и конфиги в профиле Windows |
| Разовые проверки, линтеры | `docker run --rm <образ:точная версия>` | глобальная установка ради одного запуска |

Временные файлы — во временной папке сессии, не в репозитории и не в домашней папке.
Всё, что поставлено или создано для задачи, перечислить пользователю и убрать по завершении,
если оно больше не нужно.

## Инфраструктура — как код

- Серверы, firewall, ключи, DNS описываются в репозитории (OpenTofu, папка `infra/`),
  а не создаются командами CLI вручную. Изменения: `plan` → проверка → `apply`.
- Применять изменения должен CI (GitHub Actions, environment с подтверждением), а не локальный
  компьютер: локальная сеть может не пускать к серверам Timeweb.
- Секреты — в GitHub Environments. Не хранить токены в файлах конфигурации на диске и не
  просить присылать их в чат.
- Платные ресурсы (серверы и т. п.) — только после явного подтверждения тарифа и цены.
- Ресурсы в Timeweb — в проекте «silart», имена `silart-<окружение>-<роль>-<номер>`.

## Git

- Коммитить только файлы своей задачи: `git add <пути>`, не `git add -A`. Чужие незакоммиченные
  правки в рабочей папке не включать в свой коммит.
- Push в `main` запускает деплой — пушить только по согласию владельца.
- GitHub Actions: действия закреплены по SHA, права `GITHUB_TOKEN` минимальные для каждой задачи;
  проверка — `docker run --rm -v "${PWD}:/repo" -w /repo rhysd/actionlint:<версия>`.
- Скрипты для Linux и YAML — с LF (см. `.gitattributes`).
